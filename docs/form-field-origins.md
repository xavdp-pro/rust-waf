# Form field origin and qualified exception API

A site exception may add optional `form_field`, a canonical path of at most 64 bytes and eight segments, such as `secret` or `form[fields][1]`. Each segment contains only ASCII alphanumerics or underscores. Empty/append brackets, malformed brackets and trailing suffixes are rejected. Numeric strings are not coerced: `1` and `01` remain distinct. Omission or null retains the original route/method exception and canonical fingerprint; a field declaration changes the fingerprint and must reference a body-target rule. A field exception is never returned by the route-only exception lookup.

Nested paths select an original leaf value without reconstructing an application object. Duplicate selected bindings and writes on a selected ancestor or descendant withhold its exception in either request order. Malformed related paths also withhold confirmation; a disjoint sibling array remains separate. Request keys longer than the bounded key-decoding budget conservatively withhold nested exceptions without allocating metadata for those keys. `FormPath` exposes the canonical segments for application adapters. PHP-specific dot/space/NUL aliases, coercion and dispatch still require independent adapter validation; this API does not authorize a nested application consumer.

The scanner selects original form values using one strict URL decoding of the name. Original `&`/`=` boundaries identify values; percent decoding of a value never creates a new parameter origin. Selected scalar duplicates, including encoded name aliases or valueless duplicates, remove that binding. Only configured names consume metadata, regardless of unselected parameter count. Complete raw and decoded body views are still inspected and validated; forwarded bytes never change. Decoded-view span offsets follow changes in byte length, including Unicode and later lossy decoding. No body views or values are retained in a completed scan.

For a field-target rule, a bounded Thompson scanner propagates the earliest start reaching each NFA state at each byte position. Earlier starters run first, and the anchored start at the current Unicode boundary runs last. Alternative and greedy priority cannot hide paths: every accepting end is checked. Paths at the same state/position have identical future transitions; if the earliest start and accepting end fit one field, every later start reaching that state fits it too. A cross-field or unscoped accepting interval prevents every field exception for that rule. An internal ordering/disagreement failure denies forwarding.

The scanner records the set of touched original fields across complete raw/decoded views, never occurrence strings or per-match intervals. Every touched field must independently satisfy its own route/method exception and adapter confirmation; one configured exception cannot cover another field. Caches retain two arrays of start offsets plus visited/consuming state lists and an epsilon stack, bounded by the one-MiB compiled NFA. They are allocated lazily and reused between views. For a fixed automaton, work is linear in input length and memory does not grow with occurrence count. Compilation failures and patterns with any zero-length match prevent startup. Finding an unscoped hit may stop provenance scanning, but complete normalization and syntax validation continue before forwarding.

`Inspector::inspect_scanned_with_fields(request, effective_method, confirmed_fields)` requires the application adapter to confirm a scalar binding and actual consumer. Default inspection confirms nothing. Query, path, header or unattributed-body matches cannot borrow the form exception. Route/method scope and rule/profile provenance remain enforced. Successful exception matches retain their declaring profile, and their high-confidence flag cannot start a ban because the existing proxy excludes excepted matches.

Application confirmation is not a client header. The adapter must independently validate its parser's key normalization, arrays/collisions, selected action, alternative dispatch and actual method. The shared engine's name semantics deliberately do not invent PHP normalization. WordPress can now confirm pwd on explicitly evidence-bearing site login consumers; default profiles still confirm nothing. An exception alone cannot weaken inspection, including when a client sends a forged confirmation header. No generic password exception is enabled automatically. See [the consumer contract](../crates/waf-wordpress/README.md).

Current scope supports multiple uniquely bound URL-encoded and explicitly qualified multipart UTF-8 text leaves, including canonical nested paths, with independent scopes and application confirmations. JSON bindings need further implementation and qualification. Unapplied field candidate statistics are implemented at source level but need deployed qualification. WordPress supports explicit login pwd and opt-in canonical AJAX form consumer contracts; actual plugin consumers still need installation analysis and qualification. This checkpoint is a prerequisite, not completed site compatibility. Do not enable a site rule until actual consumer, positive/negative method/dispatch/permission cases and resource measurements qualify it. Complete the broader field/visitor requirements before full acceptance.

An exhaustive differential test compares the tagged scanner against every anchored all-match start/end search on short ASCII/Unicode/newline inputs, including anchors, boundaries, alternations and greedy/lazy repetitions. Two multi-field tests cover per-field confirmations/scopes, decoded views, siblings, aliases and cross-field alternatives. Existing tests cover canonical/encoded names and values, decoded separators, UTF-8/lossy offsets, duplicate/valueless bindings, double-encoded names, cross-field and same-start alternatives, Unicode boundaries, a 256-KiB repetitive greedy case, zero-length startup rejection, all seven starter automata, query/header/route/method isolation, non-form bodies, syntax/depth failures and bounded metadata with 100,000 unselected parameters. Diagnostic decoding is compared with complete legacy views and error codes. A neutral protocol group proves field configuration and a forged header still receive correlated pre-backend denials without adapter confirmation.

Reproduce using `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo fmt --all -- --check`, `python3 tools/check_repository.py` and `python3 observability/evaluate_waf.py --self-test`. These tests are authored implementation fixtures, not independently labeled application effectiveness, actual WordPress password authentication, browser workflows or deployed concurrent resource acceptance.

`Match.unapplied_field_profiles` is omitted when empty. A local existence search over each disjoint original field span uses the complete haystack for anchor/boundary context. It records only scoped, confirmed profile IDs if exception_profile remains null; candidates cannot suppress a detection or ban. The collector counts each profile once per matched rule, distinct from applied exceptions. This captures partial qualification across encoded views without logging names/values or pretending the entire rule was excepted. The extra cache is bounded by the same compiled NFA; actual concurrent resources still require candidate measurement.

## Multipart origins

Multipart text origins require a single unambiguous boundary parameter and strict CRLF framing, with no preamble, extra epilogue or unsupported part headers. A borrowed physical layout records only bounded names, file flags and value ranges. An independent Multer prepass must agree on every name, file flag, byte value and part count before origins are assigned. Unsupported layouts or media parameters withhold origins while ordinary syntax inspection remains active; malformed syntax and limits still deny forwarding. This is a conservative origin contract, not a complete MIME/PHP compatibility parser.

Only unique selected UTF-8 text values can receive an origin. Literal MIME field names are not URL-decoded. Duplicate, related malformed or ancestor/descendant bindings withhold exceptions. File bytes, filenames, field names, part headers and cross-part match hulls cannot borrow a text exception. Whole-body raw inspection and existing per-part raw/decoded views remain complete. Binary unselected parts retain their inspection and contribute to correct lossy offset mapping; forwarding preserves original bytes.

The extra parsing pass and metadata are bounded, but artifact-specific concurrent memory and latency still require measurement before deployment. WordPress multipart confirmation requires explicit media opt-in and actual handler/FPM/schema/workflow qualification; it does not grant application authorization.
