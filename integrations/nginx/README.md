# Nginx integration

Keep the public server responsible for TLS, ingress identity, optional outer authentication, transport limits, explicitly public static assets and a protected read-only statistics location. Every dynamic location includes [the proxy snippet](proxy-location.conf). Do not rewrite the request before Rust inspection: application rewrites belong in [the isolated FastCGI bridge](backend.conf.example). A proxy_pass without a URI preserves the original request URI in these locations; qualify the installed Nginx behavior rather than guessing from normalized $uri.

The public server never contains fastcgi_pass, a dynamic cache fallback or another application upstream. Disable upstream retries and X-Accel-Redirect interpretation at the public proxy. Static locations must use an explicit asset scope, deny writes, check file existence and precede no secret/source denial. Do not use a broad public try_files that can serve arbitrary application files. Backend restrictions must retain denied uploads, secret files and installation-specific redirects/rewrites.

Install the bridge socket under a root-owned parent directory with group traversal restricted to the gateway and Nginx identities. A world-accessible socket node is insufficient without traversal, but explicit socket permissions are preferable where supported. The PHP application UID must belong to neither gateway nor Nginx groups and must receive EACCES on both paths. Never publish a backend TCP listener. The PHP socket is accessible only to the Nginx identity. Both Nginx blocks can share that identity; the public proxy configuration is a trusted component.

Overwrite X-Waf-Client-IP and X-Waf-Admin-Friend using authenticated ingress and explicit friend CIDRs. Only the trusted tunnel peer may supply CDN identity; direct peers cannot gain trust by sending its header. Keep application permissions/nonces and server-side administration guards. The illustrative bridge reserves Basic credentials for outer laboratory access; installations using WordPress Application Passwords need a qualified alternative.

[Correlation configuration](correlation.conf.example) selects the generated Rust response ID, falling back to the origin ID for requests rejected before Rust or served statically. Hide the upstream response copy and add exactly one public X-Request-ID. Use the Rust ID for the internal access log and server-side FastCGI parameter. [The PHP receipt prepend](../php/execution-receipt.php) records a minimal execution receipt during controlled probes. Precreate its private append-only destination and set WAF_RECEIPT_PATH in the FPM pool environment. A positive PHP control and working log coverage are prerequisites before absence can count as non-execution evidence.

The [service example](../systemd/rust-waf.service.example) isolates the gateway, bounds workers/tasks/memory and lets systemd remove stale frontend sockets on stop. Deployers create the protected backend runtime directory at boot before Nginx. Validate syntax, start the private bridge and gateway, and prove HTTP/PHP controls before changing public routing. Stop the gateway: dynamic and direct-PHP requests must fail without PHP execution while approved static assets still work. Restart and repeat controls. Explicit operator rollback restores a saved authenticated baseline; never automatically bypass the WAF on failure.

Nginx rejection before frontend body buffering remains pending. The existing bounded local HTTP ban table rejects at the Rust stage. No reload per request or upstream API call per detection is implemented. Matched performance/resource measurements and full workflow qualification remain required. These fictional templates do not certify any deployment.
